# 旧画面の段階的な引退計画

更新日: 2026-11-04

## 目的

`/unified` を唯一の通常入口にし、旧画面と統合版に同じ機能を二重実装しない。旧画面は、必要機能の移行とデータ確認が終わるまで削除しない。

## 現在の役割

| 領域 | 旧画面 | 統合版 | 方針 |
|---|---|---|---|
| 候補を見る | 今日の候補、Keepa、Yahoo!深掘り、楽天、監視を個別表示 | Keepa・楽天・Yahoo!をまとめて取得 | 統合版を正本にし、上位3件へ集約する |
| 利益判定 | メルカリ3〜5件、現金利益、利益率、送料、Keepa参考値 | メルカリ3件、利益、利益率、入札上限 | 統合版を正本にする |
| 保存・同期 | 型落ち用データを保存 | 入札候補と検索語をPC・iPhone同期 | 統合版の候補台帳へ寄せる |
| JAN読み取り | カメラ読み取りあり | なし | 最優先で統合版へ移す |
| まとめ検索 | 9サイトを型番・JANで開ける | ラクマ・Yahoo!フリマ・ハードオフ中心 | JAN読み取りと一緒に統合版へ移す |
| 店頭確認 | JAN、ネット最安、状態・送料確認あり | なし | まとめ検索の次に移す |
| キャンペーン | 条件登録と参考計算あり | なし | 現金利益判定と分離し、後回しにする |
| 家の在庫 | あり | なし | 仕入れ候補とは別領域。別ページ化を検討する |
| 経費 | あり | なし | 仕入れ候補とは別領域。旧画面引退の必須条件にしない |
| 動作状況・バックアップ | `/status` にあり | 統合画面内にはなし | 独立した管理画面として残す |

## 移行順

### 第1段階 — 毎日の仕入れ判断

1. 統合版へJANカメラ読み取りを追加する。
2. 型番・JANから、楽天、Yahoo!、Amazon、Keepa、価格.com、メルカリ売り切れ、メルカリ出品中、Yahoo!フリマ、ヤフオク落札相場を開けるようにする。
3. 全候補を同じ候補台帳へ保存する。
4. 利益率25%以上かつ現金利益1,000円以上を満たす候補から、上位3件だけ表示する。
5. 上位3件は、最後に人がメルカリ同一商品3件を確認する。

### 第2段階 — 見送り候補を資産にする

1. 見送り理由と再検討価格を必須項目として残す。
2. 同一商品を型番・JAN中心でまとめ、過去価格と比較する。
3. 値下がり時だけ再判定し、毎回全履歴を読み直さない。
4. 件数が増えても一覧取得が重くならないよう、集計結果と最新状態を別に保持する。

### 第3段階 — 旧画面の縮小

1. 移行済み機能を旧画面では読み取り専用にする。
2. 家の在庫と経費は、必要なら独立ページへ分ける。
3. 旧画面を直接開いた場合に `/unified` を案内する。
4. 十分な併用期間とデータ照合後に、通常入口を `/unified` へ統一する。

## 旧画面を閉じる条件

- JAN読み取りと9サイト検索が統合版で動く。
- 候補の保存、見送り、再検討価格、過去価格比較が統合版で動く。
- 全候補から上位3件を選ぶ集計が動く。
- PCとiPhoneで同じ候補が見える。
- バックアップから復元できる。
- 旧画面と統合版の保存件数・主要金額を照合済み。
- 本番反映前の操作確認を完了している。

## 今は行わないこと

- 旧画面ファイルの削除
- `/` からの強制転送
- `main` への統合
- Cloudflareへの本番公開
- 家の在庫・経費の無理な統合

次の実装は「統合版へJAN読み取りと9サイトまとめ検索を移す」から始める。
